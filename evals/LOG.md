# eval-loop の記録

## 2026-11-26 r1 - 条件「ダミーのエクセルシートで請求書作成」(初回)

- 読み方: 架空の Excel (本物のシート名・見出し、作り物の金額・住所) を、Excel 読込 → 番号・日付 → 請求書 PDF → 通知メールに通して採点する。
- 課題 4 つ × 1 回: `expense-normal` / `fiscal-boundary` / `patent-negative` / `unregistered-code`。採点役は `Explore` を 4 体。
- 結果: 受け入れ条件 22/22 合格 (6/6・5/5・6/6・5/5)。`checks` の失敗 0。
- 直した失敗の検査: `patent-negative` の `checks` は、マイナス金額の修正 (`patent-sheet.ts`、利用者の報告 2026-11-26) を外すと
  「a negative claim refused the whole workbook again」で失敗し (請求書 0 枚)、戻すと通る (4 枚)。前 → 後: 失敗 1 → 0。
- 層ごとの失敗: なし。記録だけにしたもの: なし。
- ゲート: 1 `tsc`・`build` 通過 / 2 前のラウンド無し (初回) / 3 失敗 1 → 0 / 4 全条件合格 / 5 初回なので基準として記録。
- 時間とトークン (基準): 生成 約 0.6 秒 (4 課題)、採点役 4 体で約 11.5 万トークン・各 12〜22 秒。
- 対象外: PDF の見た目 (配置・はみ出し) はテキストでは判定できない。画面 (`/invoices`) の Saved invoices の再読込の修正もこの評価では測れない。

## 2026-11-26 r2 - 条件「Excel のセル位置とシート名が多少ズレても読める」

- 読み方: 列・行の挿入 (2 列 3 行、1 列 3 行など) と、シート名の揺れ (全角の `＿` `（2）`、前後の空白、`FY2026`、`_` と `-`) で、
  ズレていないときと同じ請求書ができる。候補のシートが 2 つ以上なら推測せずに断る。利用者の選択: 名前は正規化して照合、位置は行と列の両方。
- 課題: 常設 4 (r1 から) + 新規 5 = 9 課題 × 1 回。新規: `expense-layout-shift` / `patent-layout-shift` / `expense-sheet-name` / `patent-sheet-name` / `sheet-name-ambiguous`。
- 直す前 (`r2-before`、`checks` で機械的に数えた): 5 か所の失敗 (シート名 3、位置 2)。層はどれも Excel 読込。
- 直したこと (1 回に 1 つ):
  1. シート名: `xlsx-sheet.ts` の `normalizeSheetName` / `resolveSheetName` (完全一致が優先、正規化して 1 つだけ一致すれば読み、警告に実際の名前、2 つ以上は候補を挙げて断る)。失敗 3 → 0。
  2. 位置: `locateLabels` (決め打ちの列にあればそこ、無ければ上の方の全列から探す。数が合わなければ断る)。値はラベルの右隣、会社名と金額の列の並びは保つ。失敗 2 → 0。
- 結果: 新規 5 課題の受け入れ条件 24/24 合格 (5/5・5/5・5/5・5/5・4/4、採点役 `Explore` 5 体)。`checks` の失敗 0。
- 後退の確かめ: 常設 4 課題の `result.json` は r1 と時間以外が同一 (モデルを呼ばずに比較)。採点は r1 の 22/22 を引き継ぐ。
- ゲート: 1 `tsc`・`build`・lint (変えたファイル) 通過 / 2 後退なし / 3 失敗 5 → 0 / 4 全条件合格 / 5 1 課題あたりの採点は約 3 万トークンで r1 と同程度 (常設分は比較で済ませたので合計は r1 より少ない)。生成は 9 課題で約 0.6 秒。
- 残り: 本物の Excel で、決め打ちの位置どおりに今までと同じく読めるかの確認 (評価では本物を開かない)。シート内に同じラベルが余分にあるとき (例: `Claim amount:` が 3 つ) は断るので、本物にそういう箇所があれば読めなくなる。
